Sensors & cameras

Cameras count people the patient list cannot know about (visitors). Smoke, heat and gas sensors raise alerts; the commander confirms them before routes change. Here a device simulator stands in for the hardware.

Cameras: people counted

Each count becomes that many visitors in the next run. Edit a count, or import a counts file.

Device simulator

Schedule a false alarm to practise the commander's decision. It is used in the next Live run.

    How real devices would connect: a sensor or people-counting system sends an event (device id, kind, place, value, time) to the HEALTH-11 server; the server checks the device belongs to that hospital and shows the alert to the commander. This prototype does not connect to real hardware.

    Sensors in the building

    Smoke detectors see smoke and fire, heat detectors see fire, gas detectors see chemical spills. Each answers after the sensor response time set in Parameters. Status shows the current Live run.

    Compare plans

    Run the same scenario many times. People's speeds and delays vary from run to run, so results are shown as an average with the fastest and slowest run.

    Choose a scenario and run the comparison. Eight plans × 10 runs takes a few seconds.

    Drill check

    Compare the model with what happened in a real drill: when each person left and by which exit. The gap shows how far to trust the model, and which settings to change.

    The drill record loaded now is made up (random numbers) so the page can be shown. It is not a real drill and says nothing about the model's accuracy. Import your hospital's own drill record to check the model.

    Building data

    Load a building from the HEALTH-11 export files or from this prototype's own file. Everything is checked before it is used.

    From HEALTH-11 CSV files

    The floor plan export (record_type, name, type, x, y, …), plus patients and staff exports. One floor per load.

    Other files

    Times exported from a fire model (for example a CFD tool). They become a scenario named "Imported fire model". The prototype does not run a fire model itself.
